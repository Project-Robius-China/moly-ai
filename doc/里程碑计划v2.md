## Stage 1: 对接 crew-rs（预计 2-3 周）

**目标**: 打通 moly-ai 和 crew-rs，使得 moly-ai 可以接入 crew-rs 生态

**总预计时间**: 10-14 天（使用 AI Agent 加速后：7-10 天）

### 任务列表

1. ~~**升级 moly-ai 的 OpenAI Compatible 支持**~~ ✅ 已完成
   - aitk 中已实现完整 OpenAI Chat Completions 标准参数支持

2. ~~**实现 SSE 对接 crew-rs**~~ ✅ 已完成
   - CrewRsClient 已合并到 mainline，通过 SSE 流式对话正常工作

3. ~~**WebSocket Gateway 中间层**~~ ❌ 已取消（Deferred）
   - **取消原因**: 经分析 OpenClaw 的 WebSocket 实现，发现其本质是
     "SSE over WebSocket"——仅用于单向流式推送，未真正利用双工通信。
     crew-rs 已有 SSE gateway 且工作正常，加 WebSocket 中间层 = 额外
     复杂度 + 无新功能。待未来有明确双工需求时再评估。

4. ~~**工具审批集成**~~ ⏸️ 已推迟（Deferred to crew-rs side）
   - **推迟原因**: 经调研 crew-rs 代码库，发现：
     - crew-rs 已有 `SafePolicy` 的 `Decision::Ask` 枚举和 `HumanRequest/Response`
       通道，但这些**只用于管道节点(Pipeline)级别**，未接入工具执行层
     - SSE 的 `tool_start`/`tool_end` 是**事后通知**，不是事前审批请求
     - 要实现真正的工具审批闭环，需要 crew-rs 侧先改造（在工具执行前暂停
       等待外部确认），不在 moly-ai 单独控制范围内
   - **后续计划**: 待 crew-rs 接通 `SafePolicy::Ask` → 工具执行层后，
     moly-ai 可复用已有的 `ToolRequestLine` UI 组件快速集成

5. **Robrix 集成**（预计 2-3 天）
   - 研究 Robrix 接入需求（0.5 天）
   - 实现 crew-rs 连接（1 天）
   - 测试集成（1 天）
   - 文档（0.5 天）

**Stage 1 交付物**:
- ✅ moly-ai 通过 SSE 连接 crew-rs，流式聊天正常工作
- ⏸️ 工具审批流程（推迟，等 crew-rs 侧支持）
- 🔲 Robrix 成功集成

## Stage 3: 记忆系统增强（预计 6 周）

**目标**: crew-rs 的记忆增强和记忆展示查询

**总预计时间**: 24-30 天

crew-rs 对比 openclaw 的关键性差异在于有全局跨越 session 的记忆，基于 md 和 Hybrid Search

### 任务列表

#### 3.1 记忆增强功能（预计 2-3 周）

1. **增加 memory API 端点**（预计 2-3 天）
   - 设计 memory API 接口（0.5 天）
   - 实现 `memory.search` 端点（1 天）
   - 实现 `memory.save` 端点（0.5 天）
   - 实现 `memory.list` 端点（0.5 天）
   - 测试（0.5 天）
   - 通过 HTTP/SSE 端点实现 memory 操作

2. **增强记忆检索功能**（预计 3-4 天）
   - 研究当前 `recall_memory` 实现（0.5 天）
   - 实现混合检索（BM25 + 向量）（2 天）
   - 优化检索性能（1 天）
   - 测试（0.5-1 天）
   - `recall_memory` 支持混合检索（当前只支持实体名精确匹配）

3. **自动记忆提取**（预计 3-4 天）
   - 设计提取策略（0.5 天）
   - 实现 LLM 提取逻辑（2 天）
   - 集成到对话流程（1 天）
   - 测试（0.5-1 天）
   - 对话结束后，LLM 自动提取关键信息保存到 MEMORY.md

4. **记忆自动压缩**（预计 2-3 天）

   - 实现 LLM 压缩逻辑（1.5 天）
   - 触发机制（0.5 天）
   - 测试（0.5 天）
   - 当 MEMORY.md 超过 10KB 时，LLM 自动压缩摘要

#### 3.2 记忆可视化（预计 2-3 周）

5. **记忆可视化 UI**（预计 4-5 天）

6. **记忆编辑/删除功能**（预计 2-3 天）
   - 实现编辑界面（1 天）
   - 实现删除功能（0.5 天）
   - 实现批量操作（1 天）
   - 测试（0.5 天）
   - 用户可以在 UI 中编辑/删除记忆条目

7. **记忆导出功能**（预计 1-2 天）
   - 实现 Markdown 导出（0.5 天）

## Stage 4: 安全性增强（预计 3-4 周）

**目标**: 安全性增强，防止 crew-rs 执行危险操作或泄露用户密钥

**总预计时间**: 15-20 天

### 任务列表

1. **启用安全沙箱**（预计 2-3 天）
   - 配置沙箱默认开启（0.5 天）
   - 测试沙箱隔离（1 天）
   - 性能优化（1 天）
   - 文档（0.5 天）

2. **路径黑名单监测**（预计 2-3 天）
   - 实现路径检测逻辑（1 天）
   - 配置黑名单（0.5 天）
   - 测试拦截（1 天）
   - 错误提示优化（0.5 天）
   - 支持监测敏感目录：
     - `~/.ssh`（SSH 密钥）
     - `~/.aws`（AWS 凭证）
     - `~/.config`（配置文件）
     - `/etc`（系统配置）
     - `/sys`, `/proc`（系统目录）

3. **扩展 SafePolicy 危险命令列表**（预计 2-3 天）
   - 研究常见危险命令（0.5 天）
   - 扩展命令列表（1 天）
   - 实现检测逻辑（1 天）
   - 测试（0.5 天）
   - 检测危险操作：`rm -rf /`, `chmod 777`, `dd`, `mkfs`, fork bomb 等

4. **敏感文件检测**（预计 2-3 天）
   - 实现文件类型检测（1 天）
   - 配置黑白名单（0.5 天）
   - 测试（1 天）
   - 文档（0.5 天）
   - 检测：`.env`, `.zsh`, `.ssh`, `config`, 私钥文件等

5. **实时审批机制**（预计 3-4 天）
   - 设计审批协议（0.5 天）
   - 实现审批 hook（1.5 天）
   - 实现审批 UI（1-2 天）
   - 测试（0.5 天）
   - 危险操作通过现有通信通道请求用户确认

6. **审计日志系统**（预计 2-3 天）
   - 设计日志格式（0.5 天）
   - 实现日志记录（1 天）
   - 实现日志查询（1 天）
   - 测试（0.5 天）
   - 记录所有不安全操作

7. **安全配置面板**（预计 2-3 天）
   - 设计配置 UI（0.5 天）
   - 实现配置界面（1-2 天）
   - 测试（0.5 天）
   - 用户可以配置沙箱、黑名单、审批策略

**Stage 4 交付物**:
-  安全沙箱默认开启
-  危险操作被正确拦截
-  敏感文件受到保护
-  审批流程完整
-  审计日志正常记录
